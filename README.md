# 오늘 하루, 어디서 뭐 할까 🌤️

주소와 시간을 입력하면 그 지역의 날씨를 조회해 **오늘 할 만한 활동**과
**반경 3km 내 갈 만한 곳**(공원·관광지·문화시설·레포츠·카페·맛집)을 추천하는
단일 페이지 웹앱입니다.

- 기상청 단기예보 API
- 카카오 로컬 API (주소·키워드·카테고리 검색)
- 한국관광공사 TourAPI
- 지도: OpenStreetMap / 카카오맵

## 1. 프로젝트 개요

“오늘 날씨에는 무엇을 하면 좋을까?”라는 일상적인 고민에서 출발한 프로젝트입니다.

사용자가 현재 주소와 날짜, 시간대를 선택하면 해당 지역의 기상 정보를 분석하고, 날씨에 적합한 활동과 반경 3km 이내의 관광지를 추천하도록 설계했습니다. 여러 공공데이터와 지도 API를 연결해 흩어진 정보를 하나의 화면에서 확인할 수 있도록 구성했습니다.

- 프로젝트 유형: 개인 데이터 활용 프로젝트
- 주요 결과물: 반응형 웹 기반 활동 추천 서비스
- 최종 파일: `오늘하루_어디서뭐할까_.html`
- 핵심 기능: 위치 검색, 기상 분석, 활동 추천, 주변 장소 검색, 지도 시각화

---

## 2. 기획 배경

날씨 앱에서는 기온과 강수확률을 확인할 수 있지만, 그 정보를 바탕으로 실제로 무엇을 하면 좋은지까지 판단하려면 사용자가 여러 서비스를 추가로 찾아봐야 합니다.

이 프로젝트에서는 단순한 날씨 조회를 넘어 다음 질문에 한 번에 답하는 것을 목표로 했습니다.

- 오늘 빨래나 세차를 해도 괜찮을까?
- 산책이나 러닝은 어느 시간대가 좋을까?
- 날씨에 맞는 주변 관광지는 어디일까?
- 한낮에 덥거나 비가 오면 어떤 실내 활동이 좋을까?

이를 위해 주소, 기상 정보, 생활 활동, 관광지 정보를 결합한 추천 서비스를 기획했습니다.

---

## 3. 서비스 이용 흐름

1. 사용자가 현재 주소를 입력합니다.
2. 오늘부터 3일 이내의 날짜를 선택합니다.
3. 오전 또는 오후 시간대를 선택합니다.
4. 입력한 주소를 좌표와 기상청 격자로 변환합니다.
5. 선택한 지역과 시간대의 날씨를 분석합니다.
6. 날씨에 어울리는 활동 3가지를 별점과 함께 추천합니다.
7. 반경 3km 이내의 관광지 6곳을 지도와 목록으로 제공합니다.
8. 장소를 선택하면 카카오맵에서 위치를 확인할 수 있습니다.

## 4. 활용 데이터 및 API

### 카카오 로컬 API

사용자가 입력한 주소를 위도와 경도로 변환하는 지오코딩에 활용했습니다. 초기에는 VWorld 지오코더 API를 검토했으나 해외 IP 환경에서 응답이 불안정해 카카오 로컬 API로 변경했습니다.

### 기상청 단기예보 API

선택한 날짜와 시간대의 다음 정보를 조회하는 데 활용했습니다.

- 기온
- 하늘 상태
- 강수확률
- 강수량
- 습도
- 풍속 및 풍향

기상청 API는 위도와 경도가 아닌 격자 좌표를 사용하므로, 위·경도를 `nx`, `ny` 좌표로 변환하는 과정을 추가했습니다.

### 기상청 중기예보 API

지역별 중기 육상예보와 기온예보를 확인하기 위해 별도의 지역 매핑표를 구성했습니다. 법정동코드 10자리와 기상청 예보구역 코드를 연결해 지역에 맞는 데이터를 조회할 수 있도록 했습니다.

### 한국관광공사 TourAPI

입력한 주소 주변의 관광지, 문화시설, 레포츠 장소 등을 검색하는 데 활용했습니다. 장소의 거리와 유형을 함께 제공하고 날씨 조건에 따라 추천 우선순위를 조정했습니다.

### 전국 도시공원 정보 데이터

공원 나들이와 야외 활동 추천 범위를 넓히기 위해 공공데이터 기반 도시공원 정보를 추가로 검토했습니다. 프로젝트 파일에 데이터가 없는 경우에는 TourAPI의 공원 및 관광지 정보를 대체 데이터로 사용하도록 구성했습니다.

## 5. 주요 기능

### 날씨 정보 시각화

숫자와 텍스트만 나열하지 않고 선택한 날짜와 시간대의 날씨를 한눈에 이해할 수 있도록 구성했습니다.

- 시간대별 기온 및 날씨
- 강수확률과 습도
- 풍속과 풍향
- 날씨 아이콘
- 최고·최저기온
- 야외 활동 적합도 요약

선택한 날짜와 오전·오후 정보를 결과 상단에 강조해 사용자가 현재 어떤 조건의 결과를 보고 있는지 쉽게 확인할 수 있도록 했습니다.

### 날씨 기반 활동 추천

활동을 다섯 가지 주제로 확장하고, 날씨 조건에 가장 잘 맞는 활동 3가지만 선별해 보여주도록 구성했습니다.

#### 나가서 운동해요

산책 · 러닝 · 등산 · 자전거 · 풋살 · 배드민턴

#### 밖에서 놀아요

피크닉 · 캠핑 · 낚시 · 공원 나들이 · 드라이브 · 사진 촬영

#### 운동은 못 참지, 실내 운동

헬스 · 요가·필라테스 · 수영 · 볼링 · 탁구 · 실내 클라이밍

#### 실내에서 즐겨요

영화 · 전시회 · 박물관 · 쇼핑몰 · 아쿠아리움 · 보드게임카페

#### 집 밖은 위험해

빨래 · 환기 · 독서 · 홈트 · 영화 보기 · 휴식

각 추천 카드에는 다음 내용을 포함했습니다.

- 활동 주제
- 활동 이미지
- 추천 활동명
- 별점
- 추천 이유
- 권장 시간대
- 날씨에 따른 주의사항

### 주변 장소 추천

현재 위치를 기준으로 반경 3km 이내의 장소 6곳을 제공합니다.

- 장소명
- 장소 이미지
- 장소 분류
- 현재 위치와의 거리
- 추천점수
- 간단한 소개
- 카카오맵 연결

표에서는 사용자에게 불필요한 위도와 경도 값을 제거하고 번호, 장소, 분류, 거리, 추천점수만 남겨 가독성을 높였습니다.

### 지도 시각화

추천 장소 6곳을 지도 위에 표시하고 장소 목록과 연결했습니다. 초기에는 지도가 세계지도 크기로 표시되는 문제가 있었지만, 조회 완료 후 추천 장소가 포함된 반경 약 3km 영역으로 자동 확대되도록 수정했습니다.

## 6. 주요 문제와 해결 과정

### 해외 IP 환경에서 지오코딩 API 호출 실패

초기에는 VWorld 지오코더 API를 사용하려 했으나 실행 환경에 따라 응답이 실패하는 문제가 발생했습니다.

해외 IP에서도 비교적 안정적으로 주소를 검색할 수 있는 카카오 로컬 API로 변경해 문제를 해결했습니다.

### 기상청 단기예보 조회에 격자 좌표 필요

기상청 단기예보 API는 일반적인 위도와 경도가 아니라 `nx`, `ny` 격자 좌표를 요구했습니다.

주소 검색으로 얻은 위·경도를 기상청 격자로 변환하는 로직을 추가해 지역별 단기예보를 정상적으로 조회할 수 있도록 했습니다.

### 중기예보 지역 코드 불일치

기상청 중기예보는 육상예보와 기온예보에서 서로 다른 지역 코드를 사용합니다.

법정동코드 10자리, 중기 육상예보 코드, 중기 기온예보 코드를 연결한 별도의 CSV 매핑표를 구성해 주소별로 올바른 예보 지역을 선택하도록 했습니다.

### 생활기상지수 API 접근 제한

동일한 기상청 API 중 생활기상지수는 실행 환경 또는 인증 상태에 따라 403 오류가 발생했습니다.

서비스가 중단되지 않도록 단기예보에서 제공하는 기온, 습도, 강수확률, 풍속 데이터를 조합해 자외선과 체감 환경을 간접적으로 판단하도록 보완했습니다.

### 추천 장소 데이터 부족

초기 결과에서는 관광지 종류가 제한적이었습니다.

한국관광공사 TourAPI에 도시공원 공공데이터를 결합하는 방향으로 데이터 범위를 확장하고, 야외 활동이 어려운 날에는 문화시설 등 실내 장소를 우선 추천하도록 기준을 보완했습니다.

### 지도 확대 범위 오류

추천 장소의 마커는 표시됐지만 지도 화면이 세계지도 수준으로 축소되는 문제가 있었습니다.

추천 장소와 현재 위치를 모두 포함하는 경계값을 계산하고, 결과가 나온 후 지도 중심과 확대 수준을 다시 설정하도록 수정했습니다.

## 7. 디자인 개선 과정

첫 번째 결과물은 날씨와 추천 데이터를 한 페이지에 시각화하는 데 집중했습니다. 이후 실제 사용성을 높이기 위해 단계적으로 UI를 개선했습니다.

### 1차 시각화

- 위치 확인 정보는 화면에서 생략
- 날씨를 표와 이미지로 표현
- 추천 활동 3개를 별점과 함께 제공
- 관광지를 이미지, 표, 지도 형태로 제공

### 2차 인터랙티브 서비스

- 주소 입력창 추가
- 오늘부터 3일 이내 날짜 선택 기능 추가
- 오전·오후 시간대 선택 기능 추가
- 입력값에 따라 결과가 변경되는 반응형 화면 구성

### 3차 디자인 개편

서비스 이름을 **“오늘 하루, 어디서 뭐 할까?”**로 변경하고,

- *“오늘도 갈 곳을 못 정한 당신에게”**라는 부제를 추가했습니다.

또한 다음 항목을 개선했습니다.

- 둥글고 친근하면서 가독성 좋은 무료 폰트 적용
- 날짜를 오늘·내일·모레·글피로 표시
- 날짜와 시간대 선택 버튼을 한 영역에 배치
- 선택한 날짜와 시간대 강조
- 활동 영역 제목을 “오늘은 이거 어때요?”로 변경
- 장소 영역 제목을 “동네 한 바퀴 어디로?”로 변경
- 작은 본문 글자의 명도와 굵기를 조정해 가독성 개선
- 지나치게 크게 표시되던 최고기온 숫자 크기 조정
- 추천 카드에 활동 주제와 일러스트 이미지 추가
- 한 화면에 노출되는 추천 활동을 3개로 제한
- 주변 장소를 6개까지 제공
- 장소 선택 시 카카오맵으로 이동하도록 연결

## 8. 대표 사용 예시

인천 영종구 운남동을 기준으로 내일 오후를 조회했을 때 다음과 같은 정보를 제공했습니다.

- 오후 기온 28~30℃
- 강수확률 0~20%
- 습도 55~65%
- 약한 남서풍
- 한낮보다 17시 이후 야외 활동 권장

이 조건을 바탕으로 빨래, 세차, 저녁 산책 등을 우선 추천하고, 용궁사·백운산 전망대·영종씨사이드캠핑장 등 반경 3km 이내의 장소를 함께 제안했습니다.

단순히 “맑음”이라는 정보를 보여주는 데서 끝나지 않고, 사용자가 하루 일정을 결정할 수 있도록 다음과 같은 형태로 결과를 구성했습니다.

> 낮에는 빨래나 세차를 하고, 한낮에는 실내 공간을 이용한 뒤, 17시 이후에는 주변 산책 명소를 방문하는 코스
>

## 9. 프로젝트 결과

이 프로젝트를 통해 주소와 날짜라는 간단한 입력만으로 다음 정보를 한 화면에서 확인할 수 있는 서비스를 완성했습니다.

- 지역별 날씨
- 시간대별 활동 적합도
- 추천 활동 3가지
- 반경 3km 이내의 추천 장소 6곳
- 장소별 거리와 추천점수
- 지도 위치 및 카카오맵 연결

여러 API가 서로 다른 좌표 체계와 지역 코드를 사용한다는 점을 고려해 데이터 변환과 매핑 과정을 설계했습니다. 또한 일부 API가 호출되지 않는 상황에서도 핵심 서비스가 동작할 수 있도록 대체 판단 기준을 마련했습니다.

## 10. 프로젝트를 통해 배운 점

### 서로 다른 데이터의 연결이 중요하다

주소, 위·경도, 기상청 격자, 법정동코드, 예보구역 코드처럼 서로 다른 기준의 데이터를 연결해야 실제 서비스에 활용할 수 있다는 점을 배웠습니다.

### API 호출 성공만으로 서비스가 완성되지는 않는다

같은 날씨 데이터라도 사용자가 이해할 수 있는 문장과 활동 추천으로 변환해야 실질적인 가치가 생깁니다. 데이터 조회뿐 아니라 해석과 표현 방식이 중요하다는 것을 확인했습니다.

### 예외 상황을 고려해야 한다

인증 오류, 해외 IP 차단, 데이터 파일 누락과 같은 상황이 발생해도 전체 서비스가 멈추지 않도록 대체 데이터와 안내 문구를 준비할 필요가 있었습니다.

### 정보량과 가독성의 균형이 필요하다

추천 후보를 모두 보여주기보다 가장 적합한 활동 3개를 먼저 보여주는 편이 사용자의 빠른 의사결정에 더 효과적이었습니다. 기능 추가와 동시에 정보의 우선순위를 정하는 과정이 중요했습니다.

여러 공공데이터를 단순히 조회하는 데서 그치지 않고, 사용자가 오늘의 행동을 결정할 수 있는 정보로 재구성해 본 프로젝트였습니다.

## 보안 설계 — 왜 프록시를 쓰나

이 앱은 정적 페이지지만, API 키를 **브라우저에 절대 노출하지 않도록** 설계했습니다.
브라우저는 같은 도메인의 `/api/*`만 호출하고, 실제 키는
**Netlify Functions(서버) 환경변수**에만 존재합니다.

```
브라우저(index.html)
      │  fetch("/api/kakao?..."), "/api/vilage?...", "/api/tour?..."
      ▼
Netlify Functions (서버, 키 보관)
      │  Authorization: KakaoAK <KAKAO_REST_KEY>
      │  ?serviceKey=<DATA_GO_KR_KEY>
      ▼
카카오 로컬 API · 기상청 API · TourAPI
```

순수 클라이언트 코드에서는 어떤 방식으로도 키를 숨길 수 없기 때문에,
키가 필요한 호출을 서버 함수가 대신 수행하는 구조를 택했습니다.
또한 함수는 **정해진 엔드포인트만** 대신 호출하도록 화이트리스트를 두어
오픈 프록시로 악용되는 것을 막았습니다.

## 폴더 구조

```
.
├─ public/
│   └─ index.html            # 프런트엔드 (키 없음)
├─ netlify/
│   └─ functions/
│       ├─ kakao.js          # 카카오 주소/키워드/카테고리 프록시
│       ├─ vilage.js         # 기상청 단기예보 프록시
│       └─ tour.js           # 한국관광공사 TourAPI 프록시
├─ netlify.toml              # 빌드/배포 설정 + /api 리다이렉트
├─ .env.example              # 환경변수 형식 예시 (실제 키 없음)
├─ .gitignore
└─ package.json
```

## 로컬 실행

Node 18 이상이 필요합니다.

```bash
# 1) Netlify CLI 설치 (최초 1회)
npm install -g netlify-cli

# 2) 환경변수 파일 준비
cp .env.example .env
#   .env 를 열어 실제 키를 채웁니다. (.env 는 커밋되지 않습니다)

# 3) 로컬 개발 서버 실행 (함수 + /api 리다이렉트까지 그대로 동작)
netlify dev
```

브라우저에서 표시된 로컬 주소(예: `http://localhost:8888`)로 접속합니다.

## 배포 (Netlify)

1. 이 저장소를 GitHub에 올립니다. (`.env` 는 `.gitignore` 로 제외됨)
2. Netlify에서 **Add new site → Import from GitHub** 로 이 저장소를 연결합니다.
   빌드 설정은 `netlify.toml` 이 자동으로 적용합니다.
3. **Site settings → Environment variables** 에 아래 두 값을 등록합니다.
   - `KAKAO_REST_KEY`
   - `DATA_GO_KR_KEY`
4. 배포 후 사이트 주소로 접속해 동작을 확인합니다.

> 환경변수를 추가/변경한 뒤에는 재배포(또는 "Clear cache and deploy")를 해야
> 함수에 반영됩니다.

## 환경변수

| 이름 | 용도 |
|------|------|
| `KAKAO_REST_KEY` | 카카오 로컬 API REST 키 |
| `DATA_GO_KR_KEY` | 공공데이터포털 키 (기상청 + TourAPI 공용) |

`DATA_GO_KR_KEY` 는 공공데이터포털에서 재발급 시 제공되는 **Decoding 키**를
넣는 것을 권장합니다. (함수가 인코딩을 자동 판별해 처리합니다.)
